# AntiSlop UI

Adapted from `miqdadbadjuber/anti-slop` at `eece033d2727b1357a996d02e3633b5f8cdffdf2` under MIT.

- Start from product direction or a documented minimal direction. Do not invent a fashionable house style.
- Establish a focal point, intentional spacing rhythm, a limited palette, and an identity motif that serves the product.
- Reject generic template stacks: decorative gradients, glows, glass, grids, bento cards, default hero sections, and motion without a reason.
- Each component must exist because content or an interaction needs it. Vary hierarchy where content varies.
- Confirm every visible control and link works; include loading, empty, error, focus, keyboard, and responsive states before the delivery gate.
